# The A — Telegram-бот: инструкция для Claude

Бот @BusinessManagerTheA_bot (Python 3.12, aiogram 3). Работает на VPS SkyGroup как служба
`the-a-bot`, код на сервере — `/opt/the-a-bot`, обновляется из ветки `main` этого репозитория.
Подробности для людей — `README.md` и `deploy/README.md`.

## ⚠️ Репозиторий ПУБЛИЧНЫЙ

Никогда не коммить токены, пароли, `.env`, Telegram ID людей, данные клиентов, журналы
(`*.jsonl`, `state.json`). Токен и ID менеджера живут только в `/opt/the-a-bot/.env` на сервере.

## Где что менять

| Задача | Файл |
|---|---|
| Любой текст, кнопка, ссылка на фотоальбом, автоответы, команды, описание профиля | `content/texts.yaml` |
| Новый QR-код / стартовый экран | `content/texts.yaml` → `screens` (свой `start_param`) |
| Новая тема | `content/texts.yaml` → `groups.<группа>.topics` + кнопка `seg_<id>` на экране |
| Анкета (консультация, Hayat) | `content/texts.yaml` → `forms` |
| Калькулятор (расчёт и его тексты) | `bot/calculator.py` |
| Логика кнопок / экранов | `bot/handlers/menu.py` |
| Карточки для менеджера (Ксении) | `bot/formatting.py` |
| Переписка клиент ↔ менеджер | `bot/handlers/manager.py` |
| Согласование постов канала | `bot/handlers/posts.py` |
| Бизнес-бинго (I AM. IN): вопросы, подарки, розыгрыши | `content/texts.yaml` → `bingo`, логика `bot/handlers/bingo.py` |

В 90% случаев правка — только `content/texts.yaml`, код трогать не нужно.
Форматирование текстов — Telegram HTML (`<b>`, `<i>`, `<code>`, `<a href>`); символы `< > &` в
обычном тексте экранировать.

## Что нельзя ломать

1. **Формат кнопок `src:<screen>:<action>` и `calc:...`, `approve|edit|reject:<id>`.** Эти кнопки уже
   лежат в сообщениях у тысяч людей и у менеджера; если поменять формат — старые кнопки перестанут
   работать. Ключи экранов (`direct`, `ybc`, `iam`, `relocate`, `hayat`) и `start_param`
   (`ybc_lisbon`, `iam_lisbon`, `relocate`, `hayat_webinar_13jun`) не переименовывать — на них
   напечатаны QR-коды.
2. **Строка `chat_id: <число>` в карточках менеджеру** — по ней работает ответ клиенту через Reply.
3. **Журналы** (`inbox.jsonl`, `sent.jsonl`, `*_leads.jsonl`, `calculator_completions.jsonl`,
   `state.json`) — формат совместим со старым ботом, по ним ведётся учёт. Только дописывать поля.
4. **Кнопки «📸 Фото» и «📅 Консультація» — только на экране `ybc`** (так решил владелец).
5. **Рассылку (`python -m bot.broadcast ... --send`) не запускать и не предлагать запускать без
   явной просьбы человека.**

## Как вносить правку

1. Правка → `pytest -q` (все тесты должны пройти; если поведение поменялось намеренно — обнови тест).
   Для новой функции — добавь тест в `tests/test_flows.py` (там фейковый Telegram, сеть не нужна).
2. Проверка, что тексты валидны: `python -c "from pathlib import Path; from bot.content import load_content; load_content(Path('content/texts.yaml'))"`.
3. Коммит с понятным сообщением на русском или английском.
4. Чтобы правка попала в бот, она должна оказаться в `main` (пуш в `main` или слитый PR).
5. **Сообщи человеку**, что для выкладки нужно на сервере (SkyGroup → noVNC Console, вход под
   `sgadmin`) выполнить:
   ```bash
   sudo /opt/the-a-bot/deploy/update.sh
   ```
   В конце должно быть `active (running)`. Откат на предыдущую версию: `git revert` нужного коммита →
   в `main` → снова `update.sh`.

Если меняется что-то кроме текстов (логика, калькулятор) — сначала проверь на тестовом боте:
локально `.env` с токеном тестового бота и `MANAGERS_CHAT_ID` = свой ID, затем `python -m bot`.
Никогда не запускай локально бота с токеном настоящего бота — он перехватит сообщения у сервера.

## Объясняй человеку просто

Владелец и коллеги — не разработчики. Пиши по-русски, коротко, без жаргона; команды для сервера
давай по одной в отдельном блоке (в noVNC вставка — кнопкой Paste, длинные строки иногда
обрезаются).
